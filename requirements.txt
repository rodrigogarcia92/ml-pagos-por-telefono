# The ONE pin in this file, and it is load-bearing.
#
# anyio 4.15.0 made submodule access lazy: after `import anyio`, the attribute
# `anyio.from_thread` no longer resolves unless the submodule was imported
# explicitly. Starlette's (deprecated) WSGI bridge does exactly that implicit
# access, and MLflow 3.15.2 routes EVERY request — /health included — through
# that bridge. Result: every request returns HTTP 500 with
#     AttributeError: module 'anyio' has no attribute 'from_thread'
#
# This is not a broken local environment. A clean `pip install mlflow==3.15.2`
# resolves anyio 4.15.0 / starlette 1.6.0 / fastapi 0.141.1 and is broken out of
# the box. Verified 2026-09-05: with anyio<4.15, GET /health returns 200 and the
# search API returns JSON; `pip check` reports no broken requirements.
#
# Revisit when MLflow or Starlette ships a fix, then drop the pin.
anyio<4.15
